这是一个面向薄壁件在线检测场景的**超声测厚系统**。项目把超声探头、DPL 采集板卡和 C++/Qt 上位机连成一条完整数据链：持续采集 A 扫回波，解析测量数据，计算厚度并判断当前结果是否可信，最后完成界面显示、日志记录和网络输出。

我主要参与 **C++/Qt 测厚上位机、采集与数据处理、通信链路、线程时序和软件问题定位**。这个页面只保留能快速说明项目价值的内容，详细算法、源码路径和实验记录不在这里展开。

## 项目要解决什么

薄壁件在线测厚不是“算出一个厚度数字”就结束。实际系统还需要解决三个问题：

- **持续采到稳定数据**：板卡、探头和上位机需要长时间连续工作；
- **判断这一拍能不能用**：异常回波、噪声、超时和无效数据不能直接进入后续控制；
- **把结果可靠送出去**：测量值既要给现场人员看，也要通过网络接口提供给其他控制或监控模块。

超声测厚的基础关系很简单：`厚度 = 声速 × 往返传播时间 / 2`。真正的工程工作集中在回波获取、数据有效性、软件时序和系统接口上。

## 我负责的部分

- 基于 **C++ / Qt** 开发和维护测厚上位机；
- 接入 **DPL SDK / 采集板卡**，完成参数配置、数据接收和 Beam 数据解析；
- 处理厚度、水层距离等测量量，并维护当前测量状态；
- 实现 A 扫波形、厚度和设备状态显示；
- 处理配置、日志、测量数据保存以及 TCP / UDP 通信；
- 分析采集线程、UI 刷新、网络发送和定时任务之间的时序问题；
- 结合波形、日志和源码定位异常数据与软件问题。

## 系统怎么工作

**超声探头 → DPL 采集板卡 → C++/Qt 上位机 → 数据解析 → 厚度计算与有效性判断 → 数据处理 → UI / 日志 / 网络输出**

我把它看成一条工业数据链，而不是若干独立功能的集合。采集层负责拿到原始测量数据；处理层负责把数据变成可信的物理量；应用层再负责显示、记录和对外通信。

项目中还使用了一维 Kalman 对连续标量进行平滑。但这里有一个很重要的工程边界：**滤波只能降低波动，不能把无效测量变成有效测量。** 因此数据有效性判断必须先于“看起来更平滑”的输出。

## 关键工程问题

### 1. 采集和界面解耦

高频采集不能被 UI 刷新拖慢。采集、解析、显示和网络发送需要明确职责，避免一个慢操作阻塞整条测量链。

### 2. 通信协议必须有清楚边界

项目中使用固定长度通信帧与工业侧接口对接。除了正常数据，还需要显式处理字段偏移、长度、连接状态、异常帧和超时，而不是默认网络永远正常。

### 3. Windows / Qt 是软实时环境

项目对定时和线程做过优化，但不会把 Windows 调度、UI 和网络环境描述成严格硬实时系统。实际关注的是周期是否稳定、是否出现长尾抖动，以及异常时能否定位原因。

## 项目结果

这个项目最终打通了从**超声采集到上位机处理再到工业通信**的完整链路，并形成了可直接核对的 C++/Qt 工程代码，包括板卡接入、Beam 数据模型、数据接收解析、参数下发、固定长度协议、一维 Kalman 和定时线程等模块。

对我来说，这个项目最重要的收获不是某一个公式，而是完整经历了：**传感器数据进入软件 → 数据变成可信状态 → 多线程应用稳定运行 → 结果通过工业接口输出 → 出问题后能够沿链路排查。**
